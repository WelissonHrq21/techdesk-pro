# TechDesk Pro v1.1.0 - Stage 6

## Web onboarding / first-run setup

Esta etapa adiciona um onboarding web autenticado para a primeira configuracao funcional do TechDesk Pro.

## Decisoes

- O onboarding nao e publico.
- Apenas usuarios `ADMIN` autenticados podem acessar `/setup`.
- Usuarios `RECEPTION` e `TECHNICIAN` recebem `403`.
- O estado de setup fica persistido no banco em `CompanySettings`.
- A flag `setupCompleted` tambem e retornada em `/sessions` e `/me`.
- Instalacoes existentes com dados operacionais nao sao forçadas a passar pelo wizard.
- Depois de concluido, o setup nao permite novas mutacoes.
- A criacao de usuarios iniciais permite apenas `RECEPTION` e `TECHNICIAN`.

## Fluxo

1. Boas-vindas
2. Dados da empresa
3. Conferencia do administrador inicial
4. Usuarios iniciais opcionais
5. Confirmacao de rotina de backup
6. Revisao e conclusao
7. Redirecionamento para o dashboard

## Endpoints

- `GET /setup/status`
- `PATCH /setup/company`
- `PATCH /setup/admin`
- `POST /setup/users`
- `POST /setup/complete`

Todos exigem JWT valido e perfil `ADMIN`.

## Migração

A migration `20260818000100_add_first_run_setup_state` adiciona:

- `CompanySettings.singletonKey`
- `CompanySettings.setupCompleted`
- `CompanySettings.setupCompletedAt`

Para bases ja operacionais, a migration marca o setup como concluido para evitar bloquear instalacoes reais existentes.

## Estrategia de backfill

- Banco novo: nao possui `CompanySettings` e nao possui dados operacionais; a migration nao cria linha de setup concluido. Apos o seed do ADMIN, `/sessions` e `/setup/status` retornam `setupCompleted=false`.
- Instalacao existente com `CompanySettings`: a linha existente e preservada e marcada com `setupCompleted=true`.
- Instalacao existente sem `CompanySettings`, mas com dados operacionais: se houver dados em `Customer`, `Equipment`, `ServiceOrder`, `Part`, `Budget` ou `StockMovement`, a migration cria a linha singleton ja concluida.
- Duplicatas legadas acidentais em `CompanySettings`: a primeira linha por `createdAt/id` fica com `singletonKey=default`; as demais recebem `singletonKey=id` antes do indice unico.

Essa heuristica evita forcar onboarding em bases que ja operam a assistencia e mantem bancos realmente novos no fluxo de primeira configuracao.

## Comportamento do passo Admin

- Altera nome: sim.
- Altera login: sim.
- Altera senha: nao.
- Exige senha atual: nao se aplica, porque senha nao e alterada neste passo.
- Mostra senha temporaria: nao.
- Retorna ou registra password/hash: nao.

A troca de senha permanece no fluxo seguro ja existente de `PUT /me/password`.

## Validacao final

- Upgrade isolado pre-Stage 6 com ADMIN, `CompanySettings`, cliente, equipamento e OS: dados preservados, `setupCompleted=true`, `setupCompletedAt` preenchido e ADMIN legado autenticando normalmente.
- Banco novo com migrations + seed: ADMIN inicial criado, `setupCompleted=false`, onboarding concluido via endpoints reais, logout/login retornando `setupCompleted=true`.
- RBAC backend: ADMIN 200, RECEPTION 403, TECHNICIAN 403, sem token 401.
- Bloqueio pos-conclusao: `PATCH /setup/company` 409, `PATCH /setup/admin` 409, `POST /setup/users` 409, `POST /setup/complete` 200 idempotente.
- Conclusao duplicada/concomitante: duas requests retornam 200, singleton preservado e setup final concluido.
- Retomada: empresa salva permanece em `/setup/status`, setup continua incompleto e o ADMIN retoma sem perda.
- Usuarios iniciais: `RECEPTION` e `TECHNICIAN` criados com as regras existentes de senha com hash, login unico, roles e `active=true`.
- Tracking publico: mantido sem setup state, dados de admin, password ou configuracao interna.
- Stage 5/bootstrapper: harness `tests/setup/techdeskSetup.spec.ts` passou.
- OpenAPI: endpoints `/setup/status`, `/setup/company`, `/setup/admin`, `/setup/users` e `/setup/complete` documentados como autenticados e ADMIN-only.

## Regressoes cobertas

- `/me` inclui `setupCompleted`.
- Login de admin com setup incompleto direciona para `/setup`.
- Admin com setup concluido nao volta para `/setup`.
- Rotas privadas direcionam admin incompleto para `/setup`.
- Nao-admin incompleto nao consegue acessar o wizard.
- Mutacoes do setup bloqueiam depois da conclusao.
- Conclusao exige dados da empresa e aceite da rotina de backup.
- OpenAPI documenta os endpoints de setup.
