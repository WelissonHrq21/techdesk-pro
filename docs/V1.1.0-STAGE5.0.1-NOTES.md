# TechDesk Pro v1.1.0 - Stage 5.0.1 Notes

## Scope

Stage 5.0.1 fixes a P1 security issue found during independent clean-install validation of the Stage 5 setup bootstrapper.

No real secrets from the VM validation are recorded here.

## P1

Issue:

```text
Secret leakage in setup logs.
```

Affected values:

- `ADMIN_PASSWORD`
- `JWT_SECRET`
- `POSTGRES_PASSWORD`
- PostgreSQL password embedded in `DATABASE_URL`

## Cause

The Stage 5 bootstrapper executed:

```text
docker compose config
```

through the generic logged command wrapper.

`docker compose config` renders expanded environment values in YAML form. The previous redaction covered common `KEY=value` patterns, but not YAML-style:

```text
KEY: value
"KEY": "value"
'KEY': 'value'
```

## Fix

Defense in depth:

- Added `validate_compose_config`.
- Successful Compose config validation no longer writes rendered YAML to the setup log.
- The log records only `Compose configuration: OK` on success.
- On failure, stdout/stderr are captured, sanitized, then written to the log.
- `install`, `repair` and `upgrade` now use the safe validation helper.
- Error-path `compose ps` output is piped through `redact`.
- `redact` now covers `KEY=value`, YAML `KEY: value`, quoted YAML/JSON-like key/value forms and generic URL credentials.

## Redaction Coverage

Known fictitious secrets used by tests:

```text
TEST_ADMIN_PASSWORD_STAGE501
TEST_JWT_SECRET_STAGE501_ABCDEFGHIJKLMNOPQRSTUVWXYZ
TEST_POSTGRES_PASSWORD_STAGE501
```

Inputs covered:

- `ADMIN_PASSWORD=value`
- `ADMIN_PASSWORD: value`
- `"ADMIN_PASSWORD": "value"`
- `'ADMIN_PASSWORD': 'value'`
- `JWT_SECRET=value`
- `JWT_SECRET: value`
- `"JWT_SECRET": "value"`
- `POSTGRES_PASSWORD=value`
- `POSTGRES_PASSWORD: value`
- `"POSTGRES_PASSWORD": "value"`
- `DATABASE_URL=postgresql://user:password@host:5432/db`
- `DATABASE_URL: postgresql://user:password@host:5432/db`
- `postgres://user:password@host:5432/db`
- `https://user:password@example.test/path`
- `Authorization: Bearer token`
- `Bearer token`
- `publicToken: token`

Expected:

```text
No literal secret value remains after redaction.
```

## Logging Audit

`deploy/setup-core.sh`:

- `run_logged` captures stdout and stderr into a temp file.
- Both streams pass through `redact` before reaching the log.
- Command labels do not include admin password, JWT secret or PostgreSQL password.
- Setup logs are created with best effort `chmod 600`.

`deploy/techdesk`:

- `install` uses safe Compose config validation.
- `repair` uses safe Compose config validation.
- `upgrade` uses safe Compose config validation after target image values are written.
- Health failure diagnostics sanitize `compose ps` and `compose logs`.
- Terminal receives only high-level status messages, not raw Compose config output.

`backup.sh`:

- Does not echo `.env`.
- Does not print `PGPASSWORD`.
- Does not print connection strings.
- Prints backup path and SHA256 only.

Legacy `install.sh`/`install.ps1`:

- Already run `compose config` with output discarded.
- They do not write setup logs.

`docker inspect`:

- Not used by the setup bootstrapper.

Shell trace:

- No setup production script uses `set -x`.
