# TechDesk Pro v1.1.0 - Stage 4.1 Notes

## Scope

Stage 4.1 corrects Stage 4 before push by adding support for Receita Federal alphanumeric CNPJ in `Customer.document`.

This stage does not change CPF rules, public tracking, installer/onboarding, or stock reversal behavior.

## Official Reference

Implementation is based on Receita Federal guidance:

```text
https://www.gov.br/receitafederal/pt-br/centrais-de-conteudo/publicacoes/perguntas-e-respostas/cnpj/cnpj-alfanumerico.pdf
```

Rules used:

- CNPJ remains 14 positions.
- The first 12 positions may contain digits `0-9` or uppercase letters `A-Z`.
- The last 2 positions are numeric verifier digits.
- Numeric CNPJ and alphanumeric CNPJ coexist.
- Verifier digits use modulo 11.
- Alphanumeric character values use ASCII value minus 48.

## Normalization

CPF:

- Punctuation and spaces are removed.
- Only 11 numeric digits are accepted.

CNPJ:

- Punctuation and spaces are removed.
- Letters are converted to uppercase.
- Digits and letters are preserved in the canonical stored value.

Examples:

```text
529.982.247-25 -> 52998224725
11.222.333/0001-81 -> 11222333000181
12.abc.345/01de-35 -> 12ABC34501DE35
```

## Migration

No additional migration is required.

The existing Stage 4 migration stores `Customer.document` as nullable `TEXT` with a unique index and does not include a digits-only database constraint.

## Validation

Validation remains centralized in customer document helpers.

CPF:

- 11 digits.
- Verifier digits valid.
- Repeated digit sequences rejected.
- Letters rejected.

CNPJ:

- 14 positions.
- First 12 positions alphanumeric.
- Last 2 positions numeric.
- Verifier digits valid with Receita Federal modulo 11 and ASCII-minus-48 conversion.
- Numeric CNPJ remains compatible.
- Formatted and lowercase input normalize to the same canonical value.

The official sample `12.ABC.345/01DE-35` is covered by tests.

## Privacy

The Stage 4 privacy contract is unchanged:

- `ADMIN` receives `document`.
- `RECEPTION` receives `document`.
- `TECHNICIAN` does not receive `document`.
- Public tracking does not receive `document`.
- Prints do not include customer CPF/CNPJ.
- Logger redaction still includes `document`.

## Regression Coverage

Backend coverage now includes:

- Valid CPF.
- Valid numeric CNPJ.
- Valid alphanumeric CNPJ.
- Lowercase alphanumeric CNPJ normalized to uppercase.
- Formatted alphanumeric CNPJ normalized.
- Invalid alphanumeric verifier digit.
- Invalid alphanumeric length.
- Forbidden alphanumeric character.
- Duplicate masked/unmasked/lowercase/uppercase values.
- Search by formatted/lowercase alphanumeric document.
- Privacy regressions for internal roles and public tracking.

Frontend coverage now includes:

- Alphanumeric CNPJ input, formatting, validation, and normalized payload.
- Invalid alphanumeric CNPJ blocked before submit.
- Search by alphanumeric CNPJ text.
- Detail display of formatted alphanumeric CNPJ for authorized roles.
- Technician omission regression remains covered.

## Result

Stage 4.1 makes CPF/CNPJ ready for both traditional numeric and Receita Federal alphanumeric CNPJ formats before Stage 4 is pushed.
