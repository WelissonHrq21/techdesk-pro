# TechDesk Pro v1.1.0 - Stage 5.0.2 Notes

## Scope

Stage 5.0.2 fixes the P1 reboot/autostart failure found during the Stage 5.1 R2 clean Ubuntu VM validation.

No real secrets from the VM validation are recorded here.

## P1

Issue:

```text
After a real reboot, API and frontend failed with exit 127 and TechDesk became unavailable.
```

Observed after reboot:

- PostgreSQL started.
- API failed.
- Frontend failed.
- `./techdesk` disappeared.
- `.env` disappeared.
- Application operation still depended on the installer extraction directory.

## Cause

The Stage 5 R2 install ran from an extracted installer directory under `/tmp`.

Operational files remained in that extraction directory:

- `techdesk`
- `setup-core.sh`
- `docker-compose.yml`
- `.env`
- `techdesk-installation.json`
- `logs/`
- `backups/`
- `seed-admin.js`
- `nginx/default.conf`

The production Compose file also used relative bind mounts:

```text
./seed-admin.js:/app/deploy/seed-admin.js:ro
./nginx/default.conf:/etc/nginx/conf.d/default.conf:ro
```

Because the Compose runtime was anchored to the extraction directory, Docker resolved those sources to `/tmp/...`. A real reboot removed the temporary extraction directory, leaving the installed stack without required runtime files.

## Fix

Linux `./techdesk install` now separates installer source from installed runtime:

```text
installer source: temporary extraction directory, Downloads, shared folder, or current directory
installed runtime: /opt/techdesk-pro
```

The bootstrapper prepares `/opt/techdesk-pro` before generating `.env` or starting containers. It copies only required runtime files, then re-executes `/opt/techdesk-pro/techdesk install`.

If `/opt/techdesk-pro` requires privilege, the installer requires root or `sudo` before continuing. Without privilege, it fails before creating `.env`, rotating secrets, starting containers, or modifying database state.

## Persistent Layout

Official Linux runtime:

```text
/opt/techdesk-pro/
  techdesk
  setup-core.sh
  docker-compose.yml
  .env
  techdesk-installation.json
  seed-admin.js
  nginx/default.conf
  logs/
  backups/
```

Windows scripts remain best effort and are not the official production runtime path.

## Runtime Paths

Persistent by design:

- `.env`: `/opt/techdesk-pro/.env`
- metadata: `/opt/techdesk-pro/techdesk-installation.json`
- logs: `/opt/techdesk-pro/logs`
- backups: `/opt/techdesk-pro/backups`
- Compose file: `/opt/techdesk-pro/docker-compose.yml`
- bind mount sources: `/opt/techdesk-pro/seed-admin.js` and `/opt/techdesk-pro/nginx/default.conf`

PostgreSQL remains on the Compose named volume `techdesk_pgdata`. PostgreSQL is still not exposed on host ports.

## CLI

After install, operations no longer require the original tarball or extraction directory:

```sh
/opt/techdesk-pro/techdesk status
/opt/techdesk-pro/techdesk repair
/opt/techdesk-pro/techdesk backup
/opt/techdesk-pro/techdesk upgrade --version X.Y.Z
```

The installer does not create `/usr/local/bin/techdesk` automatically in this stage. A symlink can be added later as a non-destructive UX improvement.

## Upgrade Safety

`upgrade` still uses the future-safe architecture:

```text
download/extract new package
-> validate
-> sync runtime files into /opt/techdesk-pro without replacing .env/logs/backups/metadata
-> backup
-> update image tags
-> compose up
-> health/ready
-> metadata
```

Database downgrade is not implemented. File rollback remains intentionally simple in this stage: runtime file replacement is limited to deploy assets, while database recovery remains backup/restore based. A fuller runtime file rollback policy is deferred to Stage 8.

## P2 SemVer

Malformed target versions are now classified before downgrade logic.

Expected classifications:

```text
invalid -> INVALID_VERSION
1       -> INVALID_VERSION
1.0     -> INVALID_VERSION
abc     -> INVALID_VERSION
1.0.0   -> SAME_VERSION when current is 1.0.0
1.1.0   -> UPGRADE when current is 1.0.0
1.10.0  -> UPGRADE when current is 1.0.0
0.9.0   -> DOWNGRADE when current is 1.0.0
```

`upgrade --version invalid` now reports `invalid SemVer` instead of downgrade.
