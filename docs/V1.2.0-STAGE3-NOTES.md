# TechDesk Pro v1.2.0 - Stage 3

## Scope

Stage 3 adds the complete mixed budget authoring experience to the frontend.
The backend, Prisma schema, migrations, RBAC, tracking, and privacy contracts
remain unchanged.

## UX strategy

The budget form uses two explicit actions: `Adicionar peca` and `Adicionar
servico`. Each item is rendered as a responsive card with a visible type badge,
quantity, unit price, subtotal, and an accessible remove action. PART keeps the
existing part search and SERVICE uses a required free-text description.

The form supports PART-only, SERVICE-only, and mixed budgets. Empty forms show
a useful state and cannot be submitted. Pending mutations disable editing,
add, remove, cancel, and submit controls to prevent duplicate submissions.

## Validation and serialization

The Zod schema is a discriminated union:

- PART requires a selected Part UUID, positive integer quantity, and positive
  unit price. Inactive Parts remain visible in search but cannot be selected.
- SERVICE requires a trimmed description from 1 to 200 characters, positive
  integer quantity, and positive unit price.

The API client serializes PART with `type` and `partId`. SERVICE is serialized
with `type` and `description` and never sends `partId`. Browser totals are a
formatted preview; the backend remains the financial authority.

## Revision and concurrency

Revision loads every item from the latest version and preserves its type,
snapshot display, PART relation, SERVICE description, quantity, and unit price.
Consumed PART lines cannot be removed or reduced below their consumed quantity.
The previous budget version remains read-only.

An HTTP 409 revision conflict shows a specific Portuguese message, refetches the
service order and budgets, closes the stale revision, and preserves the user
session. A 403 continues to be handled without logout.

## History, stock, and printing

Budget history renders the stored `description` before any current Part name,
so later catalog changes do not rewrite old budgets. PART and SERVICE have
distinct badges. Maintenance continues to filter strictly to PART items;
SERVICE does not appear in consumption or reversal workflows.

Printing uses one compact table with the columns Type, Description, Quantity,
Unit price, and Subtotal. A single table was chosen over grouping to preserve
the existing print density and make mixed ordering explicit. It supports mixed
and SERVICE-only budgets without dereferencing `part`. Existing print privacy
is unchanged: no password, JWT, secret, or customer document was added.

## Mobile and accessibility

Budget items stack as cards below desktop breakpoints and avoid a wide item-row
table in the editing flow. Labels remain associated with controls, icon actions
have accessible names and tooltips, validation stays next to each field, and
all actions are keyboard-operable native controls.
