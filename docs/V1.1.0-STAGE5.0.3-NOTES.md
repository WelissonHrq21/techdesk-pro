## Scope

No production bootstrapper behavior was changed.

## Cause

The setup test used one helper to convert shell-returned paths into paths that Node could read.

That helper converted all `/` characters to `\`:

```text
/tmp/techdesk-setup-... -> \tmp\techdesk-setup-...
```

This was only correct for WSL paths that represent Windows files, such as:

```text
/mnt/c/Users/... -> C:\Users\...
```

On GitHub Actions Linux, the shell path `/tmp/...` was already a native filesystem path. Converting it to `\tmp\...` created an invalid path for `fs.readFileSync`.

## Fix

The test now separates shell paths from Node filesystem paths:

- native shell mode returns the shell path unchanged;
- WSL mode converts only `/mnt/<drive>/...` into a Windows host path;
- Node `fs` calls receive native host paths;
- shell conversion no longer contaminates filesystem reads.

Added direct coverage for:

- native Unix path remains `/tmp/...`;
- WSL path `/mnt/c/...` converts to `C:\...`;
- setup log path remains readable after `validate_compose_config`.
